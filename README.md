# SHIP·小红书辅助创作工作台
一个面向小红书创作者的本地辅助工作台，把「**调研 → 选题 → 文案 → 素材管理**」串成一条单页流式工作流，帮助你在对标笔记的基础上稳定地产出内容。

> 本软件为个人创作辅助工具，仅供**学习与研究**使用，禁止商业用途。请遵守小红书平台规则与相关法律法规（详见文末《合规与免责》）。

---

## 一、产品概念
SHIP **小红书笔记落地辅助创作工作台**。

解决核心用户场景：
> **"看到别人的笔记有了一点想法和灵感想做，但往往很快因为流程的复杂而无法落地"。**

SHIP 的核心主张：
1. **让执行路径变得更简单** —— 从想法到成稿，每一步都有人给你铺好路，不用自己愣着想。
2. **让流程更可视化、有方向感** —— 你能清楚看到自己走到哪一步、下一步往哪走。
3. **先做出来，而不是想到完美** —— 先跑出一版能改的东西，再在它上面迭代。

> 🌟 **「模仿」是出发的第一步。**

---

## 二、产品定位与边界
**把脑子里"一个想做的灵感"，变成"一篇小红书笔记落地稿"。**

它刻意**不解决**以下问题（交给别的产品去解决，保持自身专注）：
- **不解决账号人设定位**（这是战略问题，拆分到其他项目处理）
- **不完全解决配图生成**（只提供配图思路建议；风格对标与图片生成将拆分到单独产品）
- **不解决自动发布**（保证账号安全性）
- **不解决数据监测与运营后台**（聚焦"单篇笔记从想法到草稿"）

## 三、创作流水线：四大环节
SHIP 以流水线方式推进，**每一步产出的内容都会作为下一环的输入**，全程进度自动保存到本地。

**调研 → 选题 → 文案 → 配图**

> 既可以整链路使用，也可以拆开单独用。
> - 虽然 SHIP 是一套完整的工作流，但**文案生成**与**配图分析**两个环节也可以**脱离前置流程独立使用**
> - 如果你已经有了清晰的想法，不打算先做调研对标，直接在对应模块的输入框里写下你的想法，就可以单独跑出文案或配图分析，不必从调研一路走下来。

### 3.1 调研 · 抓对标笔记进素材库
- 支持 **关键词抓取** 与 **单篇笔记链接解析** 两种方式。
- 抓取结果沉淀到**本地素材库**，多次抓取**累加并自动去重**，不会重复存储。

**账号安全优先：**
- 调研了 30+ 种开源抓取方式后，选用**最成熟也相对安全的 OpenCLI** 方案。
- 默认设置**串行长间隔、无序间隔**，避免平台风控。
- 素材库只存本机，不上传任何云端。

### 3.2 选题 · 爆款分析与选题推荐
对已选素材做**多角度、多维度交叉分析**，内置三层拆解：
- 🔥 **爆款内核** —— 什么会火
- 🧬 **爆款基因** —— 凭什么它能成为爆款
- 🧠 **底层人性机制** —— 触动了读者的什么心理

最终推荐出**可直接脑暴扩展的选题方向**

### 3.3 文案生成 · 多策略多版本对比
- 内置 **6 种文案生成策略一次生成 3 个完整版本**，方便你横向对比、挑最好的再改。
- 开源文案方法论可供学习研究参考。你可以按需增删或改写这些提示词文件，后端会在启动时动态加载。


### 3.4 配图方案 · 让封面成为"身份吸引"
通过 **题材、内容形式类型、目标人群、图片类型** 四个维度拆解，最终给出：
1. **人群定位** —— 这条封面主要想去"勾住"谁；
2. **图片具体实现方式** —— 实拍 / AI 生成 / 找参考图，分别怎么做；
3. **后期排版建议** —— 文字怎么放、留白怎么留、关键信息放哪。

> 配图环节不做满答案，只给**清晰可落地**的思路，和文案一样留有创作者本人参与的空间。

## 四、配图方案背后的核心洞察
这是 SHIP 在配图环节最重要的一个观点。

### 4.1 小红书笔记的"破圈"特性
小红书笔记有一个特点：**如果你的某条笔记爆了，它很可能就破圈了，并不局限于某个绝对垂类。**

- 一条笔记能爆，其中的观点更可能是大多数人都有共鸣的，**——例如"情绪疗愈""逆袭成长""认知觉醒"，本质上很多垂类人群都会共鸣。**
- 也就是说，一个易爆的正文观点本身是"大众"的，并不天然属于某一个圈子。

### 4.2 封面 = 信息呈现方式 + 身份吸引
既然观点是通用的，那读者靠什么判断"这条跟我有关系"？

**封面**作为小红书笔记的主要视觉元素，决定了读者在 0.1 秒内的三个连续判断：
1. **这内容是不是我的 taste？**（审美合不合眼缘）
2. **是不是给我看的？**（这个人/这封面跟我像不像）
3. **我会不会点进去看？**（封面勾不勾得起兴趣）

所以封面本质上是一个**身份吸引**装置——它不只是"配一张好看图"，而是在**用视觉语言先与某一群人对话**。

### 4.3 先定文案观点，再选视觉"母语"
> 在确定文案之后，创作者可以再反过来思考：
> - 这条内容更想先给哪部分人群看？
> - 哪部分人群最有共鸣，最有可能积极互动？
> - 从而选择这个人群所偏好、所熟悉的视觉母语来组织封面。

- 什么叫"视觉母语"？
- 就是某个人群最习惯、最觉得"懂我"的表达方式：
- 同一个通用观点，用不同人群的"母语"去包装封面，就会"看起来是给那一类人看的"。

### 4.4 两条腿：通用观点 × 定向视觉
整合起来，SHIP 的配图哲学是：

| 维度 | 属性 | 作用 |
|------|------|------|
| **文案观点** | 通用化 | 负责"共鸣与价值"，让内容引发更多共鸣 |
| **视觉封面** | 定向化（身份吸引） | 负责"破圈后的初筛"，决定谁会觉得"这是给我看的" |

- 先用封面锁住最想吸引的那批读者。
- 再用文案"通用共鸣"被广泛传播。

## 五、核心设计思想
### 5.1 Human in the loop —— 每一步都要人来决策
SHIP 是**工作台**，不是全自动 Agent。它不追求"一键出一篇完美笔记直接发布"，而是强调：

> **每一个环节，创作者都需要参与其中、做出决策，至少要从多个选项中做出选择。**

- 调研后，创作者来挑哪些笔记进行对标分析；
- 分析后，创作者来挑哪个选题方向；
- 文案后，创作者来挑哪一版、改哪里；
- 配图后，创作者来定"这条给谁看"、选哪种视觉母语。

在整个环节流转中，上一步生成的内容输入下一环节之后，在编辑框里创作者都可以参与到优化编辑。

> 这里有个容易被误解的点：虽然我们叫它"一键"，但"一键"只是为了让流程更清晰、有工具辅助你落地，
并非完全用 AI 生成。
真正的内容选择权和优化权始终握在创作者手里。

### 5.2 为什么是"工作台"，而不是 Agent 对话流？
**视觉展示上**：多版本并排对比排版更直观，一眼看出差异，而非逐条 scroll agent 历史消息。

**流程上**：每一步的输入上下文是**清晰、可见**的——上一步给了什么、这一步用了什么、下一步往哪走，全部透明。

而 Agent 对话流是"盲盒"：
- 你可能一开始给 Agent强调了某种概念，但在真实运行中，那条强调**埋在历史消息的旧位置**，被后续对话稀释，模型注意力逐渐丢失那份约束。

因此 SHIP 选择流水线：
- **每一步的 prompt 都是重新组装，且把当前环节最需要的关键信息放在最靠下的位置，保证模型的注意力。**

### 5.3 先完成，再完美
- SHIP 的设计不追求"想一个完美选题再动手"。
- 它让你带着对标、踩着别人的脚印先跑出一版。
- 哪怕是糙一点的第一版，至少有了能改的对象——而不是卡在"开始"这一步。

## 🚀 安装与启动

依赖 **Node.js ≥ 20** 与一个 **OpenAI 兼容** LLM 接口。

```bash
git clone https://github.com/dyevenwyw/SHIP_xhs_workbench.git
cd SHIP_xhs_workbench
npm install   # OpenCLI 会随此步骤一并安装，无需单独操作
npm run dev   # 同时启动后端与前端
```

启动后打开前端页面，在界面内的「工作台配置」中填写 LLM 接口（BaseURL / API Key / 模型名）即可开始使用。

> - 前端 / 后端默认端口（5180 / 3099）为**项目默认值**，任何用户克隆后都在本机以这些端口运行；如本机端口被占用，改 `config/settings.json` 与 `web/vite.config.js` 即可。
> - 抓取/发布模块需先用 OpenCLI 完成目标站点登录；仅使用「选题 → 文案 → 配图 → 素材管理」的内容链路则无需登录。

## ✨ 功能特性
- **整页流式工作流**：调研 → 选题 → 生成文案 → 管理素材，一站到底，无需来回切换。
- **调研**：抓取指定关键词下的对标笔记，沉淀到素材库；多次抓取累加并自动去重。
- **爆款拆解**：自动抽取笔记正文、图片 OCR 文本与互动数据，分析爆款内核与选题方向。
- **文案生成**：内置多套引流文案方法论，一次生成多个版本便于对比。
- **配图分析**：基于题材、内容形式、目标人群给出可落地的配图与排版建议。
- **统一素材库**：笔记、OCR 文本自动入库、去重，可检索、可复用、可导出。
- **防风控友好的请求节奏**：串行执行 + 随机间隔，命中风控信号立即停止并提示。
- **Human in the loop**：每一步生成结果都可在编辑框内人工优化后再进入下一环节。
- **可拆开使用**：文案生成与配图分析环节也可脱离前置流程，直接在输入框输入想法单独使用。

## 🧱 技术架构
- **Monorepo**：npm workspaces，`server`（后端）+ `web`（前端）。
- **后端**：Node.js + Express，模块化路由。
- **前端**：React 18 + Vite，单页流式交互。
- **LLM**：接入任意 OpenAI 兼容的 `/chat/completions` 接口。
- **抓取依赖**：数据抓取能力来自内嵌的开源项目 **OpenCLI**。
